# Spec coverage

Maps every requirement R1..R37 in `docs/SPEC.md` to evidence. Checked by `node scripts/check-spec-coverage.mjs` (gate G13), which fails when a requirement has no row, when an evidence path does not exist, or when the text after `::` does not occur in that file. So a renamed or deleted test breaks the gate instead of leaving stale evidence.

Row format: `| R<n> | requirement | evidence | note |`. Evidence is one or more repo paths separated by semicolons, each optionally followed by ` :: name` (a test title, an `rls.sql` section header, a gate id). A row whose evidence starts with GAP names the card or the QUESTIONS entry in its note.

Test files run on chromium and on webkit (iPhone 13) unless the note says otherwise. Database claims are read back through the service role. Everything runs on the local Supabase stack only.

- M2 Realtime on production infrastructure: see the QUESTIONS entry "C9 M2 Realtime on production infrastructure".
